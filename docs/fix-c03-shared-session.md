# C03：共享登录的跨标签页隔离（R2）

2026-11-03，修改前基线edde922，承接D7/R1同页修复。沿用已确认的DEC12共享普通登录策略，不引入独立账号标签页、消息队列或Cookie认证改造。

## 根因与方案

旧401只校验本标签页内存，随后无条件删除localStorage的两个共享凭据字段，会删除另一页新登录。仅增加“先比较再删除”仍有检查和删除之间的竞争窗口。[HTML Web Storage规范](https://html.spec.whatwg.org/multipage/webstorage.html)明确要求不要假定跨进程共享存储存在锁；storage事件也不是同步锁。因此使用ID隔离删除范围，而非用事件充当事务。

1. 普通登录每次使用128位随机ID，包括相同JWT再次登录。先写`WMS_AUTH_RECORD_V2:<id>`不可变token/初始身份，再写`WMS_AUTH_CURRENT_V2`当前指针。只发布成功才更新内存；发布失败回收本次未发布记录，保留原会话。
2. 退出只删除自己的记录及资料，保留指针。指向缺失记录表示已退出，绝不退回旧格式凭据。并发新登录拥有另一ID，不会被旧页删除。资料存入`WMS_AUTH_PROFILE_V2:<id>`，不能修改或重建凭据。
3. 普通页在storage、focus、pageshow和请求入口核对共享记录。变化时先清空本页身份、阻止旧请求，再重载页面恢复共享当前账号；不把旧表单自动套用新身份。请求快照在调用API时捕获，发送前复核，覆盖Axios异步排队窗口。
4. 演示账号仍使用sessionStorage；进入/退出体验不再删除其他标签页的普通凭据。体验退出回登录页，刷新时若仍有普通共享登录则恢复该普通账号。
5. 旧普通`WMS_TOKEN/WMS_USER`仅只读兼容、不自动迁移，避免读旧数据后迁移覆盖新登录。旧格式资料只在内存更新，重新登录即使用V2；旧版页面发布后应刷新，不能承诺新旧客户端混用也具备新保护。
6. 发布新会话后回收先前ID；下一次登录回收JWT已过期的不可变记录及无凭据的孤立资料。不能按“尚未选中”删除另一个标签页正在准备的登录。JWT解码只用于清理过期缓存，授权仍由服务器签名及版本验证负责。待确认业务记录不删除。

## 边界及文件

页面重载会丢弃未保存输入，这是共享账号切换的已选规则；已发到服务器的业务可能完成，仍按原用户核对幂等记录，不因切换自动重发。前端退出没有新增后端JWT注销机制；浏览器存储可访问凭据的原安全取舍保留。旧客户端、非本源页面、浏览器全面禁止存储的产品提示不在本项扩展范围。
