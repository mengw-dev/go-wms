# 基础仓储操作手册

本手册对应当前代码的基础仓储功能。实际菜单和操作受账号权限控制；看不到按钮时先由管理员核对角色，不通过共用管理员账号解决。版本与验收范围见[收尾验收](release-acceptance.md)。

## 首次使用

1. 按[部署指南](deployment.md)配置并启动，修改管理员初始密码。真实经营环境关闭演示与公共体验账号，分配各岗位需要的权限。
2. 在“基础数据”建立仓库、库位、货品。货品条码按字符串保存，保留前导零；仓库、货品和作业库位需启用。
3. 按需从货品、库位列表打印标签，先试印并用现场设备试扫。浏览器能生成打印页不代表所有打印机、纸张和扫码枪都已适配。
4. 新系统的初始实物库存通过入库、收货、上架建立。已有库存可用盘点纠偏，但盘点不是无来源的大批量建账接口。
5. 先用少量独立测试货品走完下述闭环，再切入真实作业。公开演示环境的数据隔离与重置规则见[演示指南](demo.md)。

## 入库、收货、上架

1. “入库管理 → 入库单”新建单据，选择仓库和货品，录入应收数量；或使用 Excel 模板导入。导入结束检查成功、失败行及失败原因，不能只看任务结束。
2. 核对后提交、审核，进入收货。扫描货品条码/编码只定位本单明细，不自动增加数量或确认收货；同货品多行时仍需人工选择对应行。
3. 首次收货填写批次，核对“收货总量”和其中的不良品数量，再确认。可分次收货，不良品数量不能超过本次总量。
4. 上架时选择任务，可扫描货品核对，再扫描或搜索同仓库启用库位，核对数量后明确点击“确定上架”。只有上架完成的良品进入实际可用库存。
5. 查看入库单状态、任务进度及库存明细/流水，确认数量和批次。收货/上架未完时不靠修改历史数量强行完成单据。

完整扫码规则及跨仓同编码的现场核对要求见[扫码辅助](scan-assistance.md)。

## 出库、拣货、发货

1. “出库管理 → 出库单”新建，录入仓库、业务订单号和数量。业务订单号用于外部下单去重，不要为重试反复换号。
2. 提交并审核后，系统按批次库存首次入库时间及ID执行 FIFO 分配，生成拣货任务；审核失败先核对可用量，不代表必须增补库存。
3. 在详情或任务入口打开拣货，先领取任务。按任务到指定库位，可扫描货品核对，再核对库位、批次和数量，最后明确确认拣货。
4. 当前基础版本的拣货会扣减库存并推进发货状态；全部任务完成后单据已发货。没有单独的包装复核、承运商运单或等待装车阶段。
5. 查看单据、任务和库存流水。草稿/可取消状态按界面操作；已发货不能当作取消回滚，当前没有专门的销售退货模块。

普通逐单拣货与基础波次/播种均包含在本版；按订单规模选择一种现场流程，同一订单不能并行使用。

## 波次与播种拣货

需要合并拣货时，在“出库管理 → 波次与拣货”选择同仓已完成FIFO分配且尚未拣货的订单；手动勾选或按创建时间预选后确认组波。领取后先按来源库位/货品/批次汇总拣货，再按S01等软件槽位分货，最后逐单确认发货。拣货和分货登记现场进度，确认发货才扣减账面库存。

波次内订单不能同时普通拣货或取消；未开始拣货可撤波恢复普通流程，原库存占用保留。已拣后的短拣、纠错、异常撤波不支持，开工前确认实物；详见[波次流程与边界](wave-picking.md)。

## 库存、移库、预警

- “库存查询”按仓库、货品、批次查看明细或SKU汇总；现存量 = 可用量 + 已分配量。已分配量属于出库占用，不代表独立的质检冻结库存。
- 从库存明细行发起“移库”，选择同仓其他启用库位、数量和原因。只能移动可用量；确认立即生效，保留批次和成对流水。历史在“仓内移库”，不提供跨仓调拨。
- “库存预警”按仓库和货品配置可用量下限，查看当前缺货/低库存。预警不会自动采购、生成补货任务或发送站外通知。
- 按需导出当前筛选结果；单次上限为10000行，超限须缩小条件，不能把分页导出当作完整备份。

## 盘点与差异处理

1. 暂停待盘点范围的实物收发和移库，确认在途作业状态，再创建整仓或指定库位盘点单。
2. 核对批次并录入所有明细的实盘数，确认为零时明确输入0；未录入不等于零。
3. 审核前再次确认实物及并发作业。系统不会替你冻结仓内实物操作，审核按锁定时库存调整到录入的绝对实盘数，并记录差异流水。
4. 审核后检查明细及库存流水，可导出差异。不要把重复审核或重复建盘点单当作撤销。

## 超时、断网和刷新后

出现“待确认”时，操作可能已在服务端成功。保留原页面的操作记录，使用“恢复/核对结果/按原请求重试”，不要清浏览器存储后重新下单或换参数重发。

收货、上架、领取、拣货和盘点审核保留原请求编号恢复；移库可先只读核对已完成记录。超过界面允许的恢复期限，先核对单据、任务、数量和流水，再由人员决定后续处理。放弃本机记录不会撤销库存，切换设备或清除存储也不会撤销服务端业务。

## 日常检查与停机

- 开工检查仓库范围、待办、可用量预警和导入失败详情；仪表盘统计口径见[运营信息](dashboard-operations.md)。
- 表格默认局部滚动，桌面和手机可分别调整结果区高度；拉高只是展示偏好，不会增加每页数据量。
- 升级前停写，备份数据库和上传目录，并保留当前应用版本、迁移版本及配置；正常停止服务保留数据卷，重置脚本会删除业务数据。
- 实际经营前需落实可恢复的备份及目标环境验收；最小操作路径与本地演练结果见[收尾验收](release-acceptance.md)。
