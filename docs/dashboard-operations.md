# 仓储运营仪表盘补充

在原运营总览上接入已有库存预警、库存流水和入库导入记录。保留四张主指标卡、作业状态、待办、七日新建趋势和最近单据；不新增图表墙或大屏模式。桌面按视口一页排布，长列表与弹窗内部滚动；小屏业务区允许纵向排列，沿用日夜主题变量。

## 口径与入口

| 信息 | 实际依据 | 入口与边界 |
| --- | --- | --- |
| 可用库存为零 / 低库存 | 复用库存预警 GET，按仓库＋货品规则汇总全部批次的可用量 | 点击进入库存预警并带入仓库、OUT_OF_STOCK / LOW 状态；单位为规则项数，不汇总商品数量；未配置规则会明确提示 |
| 今日上架、发货 | 北京时间今日零点至本次统计时点的 RECEIVE / SHIP 库存流水条数 | 展示最近 8 笔，进入某条库存记录的完整历史流水；一项任务或一次发货可能产生多笔流水，因此不称为完成任务数、收货量或发货单数 |
| 近七日异常导入 | 近七个自然日（含今天）创建、当前 FAILED 或 COMPLETED 且 fail_rows>0 的导入任务 | 展示总数及最新 5 次的文件、任务号、成功/失败行和原因；可进入入库管理。包括没有生成任何订单就失败的文件；不使用只列出有关联订单的批次选择接口 |
| 积压待办 | 原 CREATED / IN_PROGRESS 中创建已超过 24 小时的任务 | 保留最早 8 项待办及原有任务/单据跳转；“超过24小时”不是已定义的 SLA 违约 |

没有独立可靠完成时间的收货/拣货任务不推算“今日完成”。不把 created_at 新建单量或可变 updated_at 冒充完成时点；原近七日趋势继续明确为新建单量、包含取消单。

导入文件可能跨仓库，因此异常导入始终为全部仓库，并注明这是历史异常，不代表当前未处理故障；不随所选仓库变化。没有自动重试、重新上传、确认处理或告警发送等写入。

## 权限与一致性

- `/dashboard/overview` 的 `activity` 仅 `wms:inventory` 可见；`import_issues` 仅 `wms:inbound:view` 可见。拒绝权限时不查询对应表，不返回内部文件路径、run_token 或任务领取凭证。
- 新增只读聚合与原汇总共用同一 repeatable-read 事务；库存流水按发生时间过滤，连接库存时逐行核对 tenant_id 与软删，按库存记录的 warehouse_id 筛选。不改业务状态、数量、锁、数据库结构或迁移。
- 继续保留仪表盘原有平台旁路汇总和精确租户 0 语义。预警独立复用已有接口，始终为当前精确租户（含 0）规则；摘要标注当前租户，和预警页一致，不与平台旁路总库存混称为同一范围。
- 预警为独立核对时点，显示 checked_at，不宣称与仪表盘其它块跨请求的原子快照。首次失败显示“—”及失败说明；同仓刷新失败保留上次数据与核对时间；切仓立即清空旧摘要；旧响应/离页响应失效。复用原手动及可见时 30 秒刷新。
