# C01：业务写入租户范围

原问题 I10，按 DEC01 实施。代码基线 `bb774a7ddeb66a6d6432e8e87d15c530521d5984`，本地实施日期 2026-11-02。

## 问题与规则

普通平台上下文允许跨租户查询，旧业务命令也沿用了该范围。例如平台审核其他租户的盘点单，会修改目标库存，却把新流水记为租户 0；批量创建库位也可能使仓库与库位的租户不同。相反，租户 0 创建自己的仓库或货品时，又可能被其他租户的同名编码误判为重复。

业务写操作现在只使用登录身份所属的精确租户，平台身份只能写租户 0 自身业务。保留已有授权平台查询；系统用户/角色管理的委派规则另由 C02 处理，不能据此禁止系统初始化、迁移或受控重置。

## 实现

- `basic/service`：仓库、货品、库位命令及事务内引用校验使用精确租户，包含写前查重和写后冲突核对。
- `inbound/service`、`outbound/service`、`stocktake/service`：手工/导入建单、状态推进、收货、上架、拣货、领取、盘点录入与审核使用同一业务租户。批量入口复用单项命令；按导入批次删除也限制筛选范围。
- `inventory/service`、`task/service`：内部事务 API 显式绑定传入 ctx 的精确租户，复用原事务；任务快照在更新前校验归属。纯参数校验保留在数据库访问之前。
- 导入 worker 的任务领取后执行和终态保存使用任务所属精确租户；全局任务发现保持原调度范围。
- 复用原 `WithExactTenant`、事务和 GORM 过滤，没有新增框架、数据库迁移或改变锁顺序。原成功请求的幂等回放优先级保留。

## 保留边界

- 不自动修复历史库存、流水或父子表错归属，不连接生产数据库。本次无法证明既有业务数据没有历史问题；发布前须只读核对并按业务证据处理。
- 已有幂等记录不重写、不删除；成功回放不产生新业务写入。
- 未改变平台业务页面的操作按钮显示；服务端按当前租户内目标不存在拒绝跨租户命令。只读业务选项及页面权限入口在 M07 单独处理。
- 本组未修改前端、迁移和部署，不把后端检查称为浏览器、race 或生产验收。
