三、出库业务流程（单号前缀 CK）— 审核即分配，拣货才实扣

1建单 DRAFTbiz_order_no
业务单号幂等
→
2提交 SUBMITTED支持批量

→
3审核 → PICKINGFIFO 锁库存（预占不扣）
按分配行生成【拣货任务】

4拣货分配行拣满 → 实扣库存
（SHIP 流水）
→
5全拣完 → SHIPPED单据终态
→
×作废 CANCELLED拣货前作废
释放预占（RELEASE）
关键设计：一张出库明细经 FIFO 可能拆成 N 条 wms_allocation 分配行（跨批次/跨库位）；审核前按 SKU ID 排序统一锁顺序防死锁，分配行按库位编码排序优化拣货路径；任一步失败整个事务回滚，不会"锁一半库存"。

库存三数量模型：stock = available + allocated（仓库 + 库位 + SKU + 批次 四元组唯一）

stock 存量实际在货架上的货
available 可用还能分给新订单
allocated 已分配被出库单锁定、待拣货
业务动作availableallocatedstock流水类型

四、盘点流程与统一任务中心

盘点单（PD）：DRAFT → COMPLETED

  • 建单时对库存拍账面快照（book_qty），支持按库位或整仓
  • 录入实盘数 actual_qty（nil = 未盘）
  • 审核时重算差异 diff，同事务调整库存 + 写 ADJUST 流水

任务中心 wms_task：作业驱动

  • 三类任务：RECEIVE 收货 / PUTAWAY 上架 / PICK 拣货
  • 状态机 CREATED → IN_PROGRESS → COMPLETED，可 CANCELLED
  • 进度原子累加，单据作废时级联取消未开始任务

五、Excel 异步导入与故障自愈

1上传建任务

POST /import：Excel 落盘，写 wms_import_task（PENDING），立即返回 task_id，接口不阻塞

→
2CAS 抢占执行

goroutine 将 PENDING→PROCESSING，多协程/多实例只有抢占成功者执行，天然防重复

→
3心跳保活

处理中每 30s 刷新 updated_at，长任务不会被补偿扫描误判为悬挂

→
4逐行幂等建单

import_task_id + Excel 行号唯一键去重，重跑自动跳过已建行；统计成功/失败行数与逐行错误

→
5结果回写

COMPLETED（全部成功）/ FAILED（0 成功），错误信息落库（上限 1000 字截断），前端每 2s 轮询进度

6悬挂补偿（自愈）

每 2 分钟扫描超时任务：PENDING 超时未抢占、PROCESSING 心跳超时；Redis 分布式锁保证多实例只补偿一次，PROCESSING 先 CAS 复位 PENDING 再重跑——服务宕机重启后任务不丢、不重

七、安全认证与可观测性

JWT 认证

登录签发 HS256 Token（可配置过期时间），Auth 中间件统一解析并向上下文注入 user_id / username。

RBAC 权限模型

用户 → 角色 → 权限点（如 wms:inbound:approve），路由级 Permission 中间件校验，内置 admin 拥有通配权限。

异步审计日志

所有写操作（非 GET）异步落 sys_oper_log：请求参数、IP、耗时、成功/失败，不阻塞主请求。

登录防护 / 开放接口

登录失败计数与临时锁定防暴力破解；外部系统集成接口支持 API Key 鉴权（出库推送）。

全链路可观测

RequestID 贯穿一次请求的所有日志；结构化日志（slog）；Prometheus 暴露业务与运行时指标。

统一接口规范

响应体统一 {code, msg, data}，业务错误码集中管理；分页结构统一；参数校验失败标准化返回。

九、核心技术设计与可靠性保障

① 并发分配库存保护

事务内按 FIFO SELECT…FOR UPDATE 锁读，再以 available_quantity >= n 条件更新数量，MySQL CHECK 约束为非负数量提供最后兜底。MySQL 集成回归测试以 100 可用库存承载 200 个并发分配请求，结果成功 100、库存不足失败 100，并校验最终三数量与恒等式。

② 单号生成器三级防线

Redis Lua（INCR+TTL 原子）→ Redis 故障降级本地 atomic 计数 → DB 唯一索引冲突重试，任何级别故障都不产生重复单号。

③ Excel 异步导入可靠性

任务表状态机 + CAS 抢占防重复执行 + 心跳 + 悬挂任务定时补偿重跑；import_task_id+行号唯一键保证重跑幂等，服务重启自愈。

④ 单据状态机 + CAS

合法后继状态转换表统一校验；状态更新带 WHERE status=前态 AND version=n，并发双击只成功一次，非法跳转（如已收货作废）一律拒绝。

⑤ 锁顺序防死锁

出库审核前按 SKU ID 排序使全局加锁顺序一致；拣货/取消统一"主单→任务→分配行"锁顺序，杜绝交叉等待死锁。

⑥ 库存流水与对账

每次库存变动同事务只增写流水（变更前后存量/可用双组值），stock=available+allocated 恒等式有集成测试守护，任意时刻可追溯对账。
