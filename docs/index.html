项目定位

基于 Go + Vue 的模块化单体 WMS

项目覆盖入库、出库、库存和盘点闭环，重点展示库存一致性、事务边界、多租户隔离， 以及一条可以由访客亲自操作和核验的真实业务流程。

业务范围明确从单据状态推进到库存变化，不把 Demo 做成孤立的页面展示。
结果可以核验自动演示结束后，可查看真实单据、任务、库存流水和操作记录。
技术深度可继续展开围绕库存模型、事务、并发、多租户和测试体系继续阅读源码。

核心业务闭环

状态和按钮名称以当前真实业务页面与 Service 为准。

02 / BUSINESS FLOW

入库

从采购来货到形成可用库存。

创建→提交→审核→收货→上架
收货生成上架任务；上架完成后在真实事务中增加库存并写流水。

出库

从客户订单到库存分配与发货。

创建→提交→审核 / FIFO 分配→拣货→完成
分配按真实库存执行，生成 PICK 任务；完成拣货后推进发货与库存扣减。

盘点

用账面快照与实盘结果发现差异。

库存快照→实盘录入→差异确认→审核调整
审核后在库存事务中应用差异，并通过 ADJUST 流水保留调整证据。

在线 Demo 如何工作

让多个访客在同一套服务上体验，但不会互相看到或修改对方的数据。

03 / DEMO SESSION
1. 分配演示账号

访客进入在线体验时，从空闲演示账号中领取一个独立租户。

2. 获取 Session 租约

登录后通过 Redis 租约锁定当前演示租户，同一账号同时只服务一个访客。

3. 操作期间续期

真实交互触发心跳续期；长时间无操作后，租约会到期并释放。

4. 退出后恢复数据

退出或重置会通过专用 bootstrap 路径恢复该租户的演示数据，不混入下一手访客。

为什么 Demo 不是假数据

场景只负责编排，业务状态、事务和库存规则仍由真实 Service 执行。

05 / ENGINEERING DESIGN

库存三数量模型

现存量、可用量和分配量保持同一套约束，避免库存分配与释放产生负数或账实断裂。

stock = available + allocated

事务与并发库存分配

状态推进与库存变更放在事务边界内，通过行锁、条件更新和版本字段处理并发竞争。

多租户隔离

业务查询和写入按租户作用域约束，展示账号拥有独立的数据空间与权限边界。

Demo Session 数据隔离

演示账号、租户、Redis 会话租约和重置流程共同保证访客互不干扰。
