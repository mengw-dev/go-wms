# 扫码辅助作业

支持把编码输入为键盘按键、以回车结束的扫码枪，也可手动输入并点“核对”。不监听全局键盘，不自动领取任务或提交数量；无需新增中间件、依赖或数据库迁移。

## 使用入口

| 入口 | 扫码行为 | 最终确认 |
| --- | --- | --- |
| 入库单详情 → 收货 | 输入货品原条码或货品编码，定位当前单据的匹配明细；同货品多行全部保留 | 逐行核对批次、收货/不良数量，再点“收货” |
| 入库单详情 → 上架 | 可选核对当前任务货品；输入库位编码，选择当前单据仓库的启用库位 | 核对目标库位与数量，再点“确定上架” |
| 出库单详情 → 拣货 | 可选核对当前任务货品；原库位/批次输入支持回车核对 | 按原流程领取任务，核对数量，再点“确定拣货” |

货品核对是辅助功能，仍保留手工操作入口。输入了货品码但尚未核对成功时，确认按钮暂停；清空货品码可回到手工核对。扫码成功不增加本次数量，重复扫描不累计库存，也不自动跳到另一条任务。

收货扫描同SKU多行时，只筛出这些行，不能据此判断应收哪个批次；操作人员选择对应行。可点“显示全部”恢复原明细。上架库位下拉支持远程搜索，首批最多100条；扫码精确查询不受首批限制。空闲与已占用但未禁用的库位均可选择，沿用原服务端允许同库位存放多批库存的规则，不引入容量或混放规则。

原标签载荷不变：货品标签是原`sku.barcode`，库位标签是原`location.code`。分字段解释，不解析码内的URL、租户或仓库信息。跨仓库允许相同库位编码，扫码只按当前单据仓库解释；现场需同时核对标签上的仓库文字，单凭原始库位编码不能证明物理所在仓库。

## 编码、查询与权限

- 去除输入首尾空白，保留前导零、大小写和内部字符，不转为数字；1–64字符，拒绝内部控制字符。按实际编码精确、区分大小写匹配，不做模糊匹配或自动补全数字。
- 查询当前单据引用的、未删除且启用的货品，使用当前基础资料条码/编码；不扫描全库，也不使用可能陈旧的条码缓存。单据历史名称和编码快照不被改写。
- 同一输入同时命中某货品编码和另一货品条码时，返回有歧义提示，不自动取第一条；可用其他无歧义编码，或清空后按单据手工核对。
- 上架查询只读当前租户、当前单据仓库的启用库位；已删除/禁用、其他仓库独有的编码均不选中。tenant_id=0同样精确隔离，不能据此跨租户查询。
- 输入框捕获自身回车并阻止表单默认提交，忽略输入法组合回车及按键长按重复事件。查询期间保持键盘焦点；结果返回时仅在该框仍获焦的情况下选中旧值，不抢走其他输入框焦点。
- 切换单据、任务、登录身份、关闭或离开弹窗时，旧查询结果失效。查询失败清除核对成功状态，不能沿用上一次成功对象。
- 不额外要求`wms:basic`资料管理权限；查询按单据查看权限保护，上架库位还要求上架权限。真正写入继续使用原收货、上架、PDA拣货接口、租约、库存校验与原请求幂等恢复。

路径前缀`/api/v1`，响应ID为字符串：

| 方法 | 路径 | 权限与参数 |
| --- | --- | --- |
| GET | `/inbound/orders/:id/scan-sku` | `wms:inbound:view`；code必填，最多64字符；返回最多2个不同货品供唯一性判断 |
| GET | `/outbound/orders/:id/scan-sku` | `wms:outbound:view`；同上，范围为该出库单 |
| GET | `/inbound/orders/:id/putaway-locations` | `wms:inbound:view` + `wms:inbound:putaway`；code精确查询或keyword编码包含查询，page/page_size（最多100）；返回list/total |

货品响应仅含id、code、name、barcode；未匹配返回空数组，未知或越权租户的单据返回不存在，无查看/作业权限返回拒绝。所有接口均为只读，确认时重新校验业务状态与库存；客户端核对不是服务端防错校验的替代。

## 设备范围

本版不含手机摄像头识别、串口/厂商SDK、GS1复合码、数量编码协议、离线写入或扫描即扣增库存。浏览器测试用键盘输入模拟扫码枪，不能代替实体扫码枪、扫描质量和仓库现场验收；打印纸张与条码尺寸边界继续见[打印说明](document-printing.md)。
