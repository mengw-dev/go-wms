## 本地备份恢复演练

专用本机MySQL8.0.46与Redis兼容实例，使用全新测试库运行正式迁移；release服务启动日志确认没有AutoMigrate。测试结束停API/worker，从该库导出并导入另一个新库，不覆盖原库。

- 恢复前后22张表、2323行数据的精确行数与`CHECKSUM TABLE EXTENDED`相同，列元数据与规范化建表语句相同；索引、CHECK、默认值与类型纳入核对。
- dump会把隐含继承的utf8mb4列字符集显式写出，最初原始建表文本比较因此失败；随后独立核对列字符集/排序规则元数据，只规范化这项同值冗余表达，不忽略实际类型/约束差异。
- SQL大小577819字节，SHA-256为`a8718226b25fad76d7f3168943fe37f2ad81de2b363cc9e538f29d81dab07a7b`；迁移14、dirty=false，库存负数或三数量关系异常为0。
- 通过真实上传接口建立一份故意损坏的xlsx测试任务，确认FAILED后保留源文件；复制文件的哈希相同。恢复点没有PENDING/PROCESSING导入任务，因此不据此宣称验证了旧在途任务换路径后继续执行。
- 恢复后使用独立Redis逻辑库和复制的上传目录启动release服务；健康、登录及业务浏览器回归结果见开发记录。已有任务文件路径的部署要求仍按备份手册执行。
- 首次连接空Redis时复现同日单号重号：唯一约束拒绝建单，部分导入行失败，没有覆盖历史单据。随后停写，恢复RK/CK/PD三个业务单号key，目标水位不降低；手册补充数据库全部租户/软删记录的已用号核对。会话与缓存未恢复，不把这次演练写成Redis全库恢复或发号自动自愈。

本轮没有配置服务器定时备份、异地保管、PITR、自动回滚或RPO/RTO。这个测试恢复点只包含隔离测试数据，不是线上备份。

## 合并与上线前的核对

1. 保留已验收的提交范围，以本合集为候选合并；再次确认不带入波次和原工作区未提交文件。合并不是把别的分支整目录覆盖到main。
2. 升级前停写并落实可恢复的数据库/上传目录备份，保存当前镜像和迁移版本。当前合集需要`000014_inventory_movements`；非空移库历史不能通过down删除。
3. 波次候选也使用过000014，原外部单候选使用过000013；将来合并这些候选时重新编号并单独验迁移，不能与本版相同编号一起发布。
4. 自定义角色按岗位授予移库等权限，修改初始密码，配置节点号、密钥和文件目录。实际经营关闭公共演示/体验账号，不向真实业务库执行`seed-demo`或reset。
5. 推送后按实际CI结果确认门禁；部署再核对前后端同一提交、迁移无dirty、就绪与登录，以及少量独立测试货品的收发闭环。推送成功不代表已经上线。
6. 在实际手机、扫码枪和打印机上试用。浏览器键盘输入与打印PDF不替代实体设备适配。

基础业务的本地收尾与目标环境交付是不同阶段。D27持续审查、仓库主数据锁竞争和其他B类边界继续保留；文件长、可选模块未做或没有逐行审查结论，不自动升级成新业务缺陷。
