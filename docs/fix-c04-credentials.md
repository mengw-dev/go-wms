# C04 第一部分：在途改密和体验账号凭据撤销

对应 D4、I34；基线 e220199，2026-11-03核对全量结果并提交。本提交只完成 C04 的凭据部分；I5 旧表单覆盖问题仍待后续修改，不将 C04 整组记为完成。

## 问题与实现

本人改密原先读取并验证旧密码后无条件保存。管理员重置、另一次改密或停用再启用在其间完成时，旧请求仍可覆盖新凭据。现在 Auth 中间件把签名内的 token_version 传给改密 Service，精确限定本人租户；写入要求启用状态、原哈希和凭据版本仍相同，否则返回40100并要求重新认证。密码校验/计算在数据库行锁外；成功保存密码与递增凭据版本是同一条 UPDATE。

演示/持久体验账号原先关闭只改 status，重开可使旧 Token 恢复有效；每次启动还会重新生成哈希并覆盖，不能据随机盐判断密码是否变化。现在按密码语义比较，只在密码或启用状态变化时递增版本。重复关闭、无配置变化的重启保持原凭据；关闭/缩容限定受管租户与账号命名，原业务数据保留。配置密码仍是公开账号的启动同步依据，访客自改后下次同步恢复配置并撤销旧凭据。

同步采用带原版本、状态、哈希及精确身份的条件写；竞争时重新读取、重新比较，最多三次，持续竞争返回错误。不引入新框架、表或长时间持锁的 bcrypt 计算。

## 文件与验证

- `internal/pkg/middleware/{auth,request_context}.go`、`system/handler/handler.go`：携带可信签名版本，客户端不能通过改密正文覆盖它。
- `system/service/auth.go`、`system/repository/user.go`：本人改密前后两次核对，条件写防覆盖；管理员重置保留其独立授权入口。
- `bootstrap/{account_credentials,demo_accounts,personal_accounts}.go`：公开账号凭据生命周期及有界竞争处理。
- `system/service/password_concurrency_test.go`：可控时序复现旧改密被重置/另一次改密/停用再启用/删除打断，拒绝后凭据不变；覆盖读取前已撤销身份、租户0越界。
- `internal/app/password_test.go`：正式迁移MySQL、签名JWT与真实路由，旧密码错误、成功改密、旧Token拒绝及新Token正常改密。
- `bootstrap/account_credentials_test.go`：两类账号无变化重启、停用重开、密码同步、缩容扩容、自改后恢复配置；并发同步已完成的新版本不再被旧快照改写。已有同名普通租户隔离测试保留。

修复前正式改密并发回归失败，前三种交错均返回成功并接受旧请求；删除交错返回旧账号不存在错误。种子回归修复前在重复启动哈希变化处失败。修复后所有专项通过。
