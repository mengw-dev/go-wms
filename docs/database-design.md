# 数据库引用完整性说明

[文档目录](README.md) · [表结构与迁移](database.md)

## 当前策略

当前迁移未建立业务外键。引用完整性主要通过应用层的租户校验、行锁与引用检查维护；唯一索引和库存 CHECK 约束提供额外保护。这里描述现有取舍，不表示外键无法用于 WMS，也不表示应用层检查能覆盖所有异常写入。

业务删除同时涉及软删除、历史单据、库存与任务。新增或修改删除路径时，必须检查真实调用链，不能仅凭数量为零认定数据可删。

## 已有约束

| 约束 | 作用与边界 |
| --- | --- |
| 唯一索引 | 约束业务编码、库存身份和幂等键等，具体租户前缀见迁移 |
| 库存 CHECK | 三数量非负与 `stock = available + allocated`，不替代业务事务 |
| 软删除 | 软删记录仍可能占用唯一键，不保证删除后能重建同编码 |
| 租户索引 | 支撑过滤查询，本身不承担租户授权校验 |

## 应用层检查

| 操作 | 当前检查范围 |
| --- | --- |
| 删除仓库 | 库存、库位、任务及入库 / 出库 / 盘点单引用 |
| 删除库位 | 库存、任务、分配、盘点单及盘点明细引用 |
| 删除 SKU | 库存、任务、入出库明细、分配及盘点明细引用 |
| 库存创建 | 锁定仓库、库位、SKU 并校验关联对象 |

实现入口为 `internal/modules/basic/service/`，引用查询见 `internal/modules/basic/repository/references.go`；历史引用查询使用 `Unscoped`。回归测试见 `internal/modules/basic/service/delete_test.go` 与 `conflict_test.go`。

## 后续变更原则

- 若增加外键，应先审计历史数据、租户关系与软删除语义，再设计迁移和回滚。
- 不用级联删除替代业务删除校验、库存事务与流水记录。
- 应用层遗漏校验或人工改库仍可能产生不一致；现有测试只证明已覆盖场景。
