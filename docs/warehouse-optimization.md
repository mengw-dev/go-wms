# 仓储作业流程与性能优化计划

本文记录待实施的改进。优先缩短操作等待、减少重复读取和写入，并用隔离环境验证业务结果。下文的查询数量来自本地测试或代码路径核对，实际收益需按部署环境和作业规模测量。

## Excel 导入调度

当前 worker 空闲时每两秒查一次任务。轻量文件若刚好错过一轮扫描，可能在开始处理前多等近两秒。页面也按两秒查询进度，任务结束到界面显示完成之间还有一段独立的等待。

API 与 worker 同进程时，任务仍写入 MySQL。事务提交后，上传入口向容量为 1 的 Go channel 发送非阻塞通知。worker 启动时检查积压，处理完一项后立即领取下一项，查空时再等待通知、兜底计时器或退出信号。短时间的多个通知可以合并，待领任务以数据库为准。数据库出错时按退避策略重查。

保留原子领取、执行凭证和行级幂等。通知遗漏或进程重启时，由启动检查和低频扫描恢复；上传请求不等待 worker。该方案无需 Redis 消息队列。如果 API 和 worker 以后拆分到不同进程，需要另行处理跨进程通知和上传文件访问。页面可在提交后立即查询一次，短时间内较快检查，随后逐步降低频率，离页或任务结束时停止。

验收分别记录排队、执行和页面展示的耗时。覆盖空闲唤醒、worker 忙时新任务到达、突发上传、遗漏通知、重启补领和数据库故障退避，并核对导入行、订单和明细没有重复写入。

## 查询与写入成本

| 场景 | 当前行为 | 改进与验收 |
| --- | --- | --- |
| 波次登记 | 每次成功登记都重新读取波次头、订单、拣货汇总和分货项。 | 测量大波次的响应大小和耗时。回执带版本和变更数据，版本连续时局部更新；打开详情、版本不连续或结果不确定时重新读取完整详情。 |
| 收货完成判断 | 单头锁内每收一行都读取全部明细。200 行逐行收货的隔离测试累计返回 40,000 行明细。 | 先用可靠的累计进度判断是否可能完成，再读取所需明细。验证并发最后收货只生成一次上架任务。若先改为按实收上架，应按新状态机重新设计完成条件。 |
| 外部订单解析 | 100 行请求在内容解析阶段发出 100 条货品查询，写入事务内另有批量引用校验。 | 按编码有界批量解析，保留锁内引用校验。核对租户隔离、大小写比较、缺失货品和历史请求回放。 |
| 库存预警 | 隔离库只配一条预警时，摘要、总数、列表三条聚合查询各读取 5,000 条库存记录。 | 先限定有预警规则的仓库和货品，再汇总相关库存。仪表盘仅需要摘要时走精简查询。核对零库存规则和租户范围，比较执行计划。 |
| 批量创建库位 | 新增少量库位也在仓库排他锁内读取全仓库编码。 | 只查本次候选编码，去重规则与数据库唯一索引保持一致。验证并发插入和大小写等价编码。 |
| 异常收口 | 12 条已发分配归于同一明细的测试中，明细更新路径执行了 13 条更新。 | 先按明细汇总再更新，在同一事务内核对已发历史、释放数量和库存守恒。 |
| 存在性查询 | 部分引用或未完成作业检查用 `COUNT` 统计全部匹配行，调用方只判断是否为零。 | 对只判断存在的入口使用可早停的查询，核对过滤条件与执行计划。 |
| 基础资料选项 | 全量加载通过串行分页保证完整性。模拟一万条记录时发出 100 次请求。 | 使用远程搜索与分页，并支持按 ID 回显已选对象。验证深分页对象可选、回显稳定。 |
| 大盘点审核 | 逐行锁读和更新，无明确明细规模边界。250 行零差异的隔离测试记录了 503 条查询或更新。 | 先确定并验证单据规模上限，再评估批量读取和标记。审核与库存调整保持原子提交。 |

## 作业状态与流程

- **PDA 租约**：部分拣货成功后，服务端已延长领取租约，页面仍可能按首次到期时间拦截作业。同步服务端确认的当前租约，历史幂等回放不能当作新续租。验收覆盖部分拣货、过期、接手及原请求回放。
- **分批到货与上架**：目前整单收齐后才生成上架任务，同一订单明细只能绑定一个收货批次。按实收分项生成上架任务时，需要同时处理多批次、累计防超收、短收关闭和任务去重。
- **盘点补盘**：现有快照只包含正库存行。支持账面为零的盘盈时，需要校验货品、批次和库位，记录补盘来源，经审核后生成库存及调整流水。
- **拣货、发货与异常恢复**：普通拣货完成分配行时会发货，波次要求显式确认发货。统一作业语义时，应明确待发实物位置、发货确认、局部异常退回和占用释放，退货上限以实际已发且未退数量为准。

查询优化可以按场景单独实施。涉及库存、租约或单据状态机的改动，先明确业务条件，再用并发、重试和失败恢复场景验收。
