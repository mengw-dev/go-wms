# 库存预警

入口为“库存管理 → 库存预警”。本功能从 main 的 18bf0a7 独立开发，该阶段未改原库存写入和锁协议；现main已整合波次，预警仍按真实可用库存计算。

## 规则与使用

- 按精确租户、仓库、货品配置唯一规则，下限为 1–2147483647，使用该货品库存计量单位。
- 汇总该仓库同货品全部未软删库存行，使用**可用量**判断；已分配库存不算可用。无库存行按零处理。
- 可用量为零：缺货；大于零且低于下限：低库存；达到或超过下限：正常。现存量即使大于零，全部被分配后仍可触发缺货。
- 暂停规则不预警。仓库或货品停用、删除后显示“基础资料已停用或删除”，不伪装成缺货，可删除失效规则。
- 页面默认“需关注”，可查看全部规则、暂停规则或正常规则；摘要按当前仓库和货品筛选统计，不随状态筛选改变。统计单位是规则条数，不把不同货品数量相加。
- 前台可见且未打开配置表单时每30秒刷新；可手动刷新。补货、释放分配等业务提交后，下次查询按当前数量恢复正常。没有后台扫描、推送通知或预警发生历史，不显示虚构的“首次告警时间”。
- “距下限差额”仅为下限减当前可用量，不是采购建议或补货任务；库存明细入口携带仓库、货品编码，并显示已清空的库存行。

规则修改、暂停、删除均不修改库存、单据、任务或库存流水。配置保存采用同仓货品覆盖式 PUT，可重复提交；并发修改按最后提交的值生效，不提供规则编辑版本冲突提示。删除释放该配置组合，重复删除成功；可重新配置。

## API、权限与隔离

路径以 `/api/v1` 开头，ID 为字符串，库存汇总量为 int64。

| 方法 | 路径 | 权限与参数 |
| --- | --- | --- |
| GET | `/inventory/alerts` | `wms:inventory`；warehouse_id、sku_keyword、state、page、page_size（最多100） |
| GET | `/inventory/alert-options` | `wms:inventory:alert:manage`；kind=warehouse/sku、page、page_size（最多100）；仅本租户启用基础资料 |
| PUT | `/inventory/alert-rules` | `wms:inventory:alert:manage`；warehouse_id、sku_id、min_available_qty、enabled（布尔必填） |
| DELETE | `/inventory/alert-rules/:id` | `wms:inventory:alert:manage`；仅删除本租户规则 |

state 支持 ALERT（默认）、ALL、LOW、OUT_OF_STOCK、NORMAL、PAUSED、UNAVAILABLE。响应含 list、total、summary、warehouses、checked_at；查询使用单个只读事务使计数、行、摘要和仓库选项处于同一快照。仓库筛选选项来自该租户已配置规则，配置表单选项由专用管理接口分页加载，无需授予基础资料修改权限。

平台 tenant_id=0 也精确隔离。原始库存聚合、规则表以及基础资料 JOIN 都显式限定租户和软删；不用 Redis 缓存，避免库存变化后读取过期预警。聚合按仓库与SKU批量查询，不逐条读取库存。

保存时仅对仓库、SKU引用持共享锁，与基础资料删除/禁用互斥；不获取库存行锁。原上架仓库排他锁不在本功能改动范围内。

内置演示/个人体验角色增加管理权限；演示重置只删除本租户预警配置并重新写入原演示种子。自定义角色需要显式授予管理权限，只有库存查看权限的账号可以查看预警和追溯库存，不能修改规则。

## 数据与发布

迁移 `000013_inventory_alert_rules` 新增 `wms_inventory_alert_rule`，唯一键 `(tenant_id,warehouse_id,sku_id)`，INT正数下限CHECK。开发AutoMigrate、正式迁移、启动CHECK验证与数量审计同步。

正式迁移顺序为预警000013、移库000014、波次000015，波次候选原000014已顺延。原工作区另有未提交的000013_external_order_source候选，不能把两个000013一起发布，该外部单候选合并前需重新编号。本功能不纳入它。down仅删除预警配置，不修改库存，但会丢失配置；正式发布和回退需先备份。

查询时会汇总当前租户库存，不承诺大库的固定时延。当前版本不含邮件、短信、自动采购/补货、动态销量预测或异常工单闭环。
