## 结论与顺序

优先统一加锁顺序，再整体细化主数据引用锁，最后减少持锁事务内的重复查询。没有发现本轮证据能够证明的错账或重复扣库；这不是全仓正确性保证。

|---|---|---|---|

## 实施边界

- 调整主数据引用锁必须保留删除/禁用与写库存互斥，库位占用更新不得覆盖管理员已经提交的禁用。
- 保留同一订单、同一波次及同一库存行的必要互斥；不为了并发直接改成无锁或SKIP LOCKED跳过FIFO库存。
- 保留成功幂等回放先于可变业务状态校验、同事务库存与流水、租户精确隔离、新事务重试及数量条件更新。
- 细化后仍需定向验证：同仓不同库位、跨仓同SKU、同库存累加、新四元组并发创建、移库相向、冻结/分配、退货/禁用与删除、同key恢复。只做对应回归，不必重跑无关前端布局。
- 上述为原审查边界；后续授权实施及验证如下，不再列为待实施优化。
