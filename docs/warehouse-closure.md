# 库存与异常收尾

本轮范围：库存数量冻结/解冻、出库异常恢复、客户退货入库。沿用 MySQL 事务、现有权限与双主题，不引入中间件。

## 业务规则

- 现存量 = 可用量 + 已分配量 + 冻结量；冻结不减少实物库存。仅可用量可冻结，解冻回到可用量。已有占用先走出库异常，不暗中撤销其他订单。
- FIFO、移库只能使用可用量；盘点调减不能侵占已分配量或冻结量。每次冻结/解冻必须填写原因并留流水。
- 普通拣货在每个分配行拣满后发货；部分拣货仅记录进度。异常登记必须确认未发实物退回原位，保留已拣满发货数量，停止剩余任务并释放全部未发占用。未发任务原进度保留在历史任务中，单据进度重新按已发数量收口。短缺扣减对应实物账，货损转入冻结。重新分配仅补未发数量；也可关闭剩余作业，保留原需求与实际发货差额。
- 异常重新分配后，历史CANCELLED任务/分配仅供审计，不阻断替换任务组波；已发分配仍参与已发量校验。确认未发实物退回后，若当前任务未开工、未绑定波次且主单无已发量，可取消订单；当前开工、波次绑定或已发货仍禁止取消。取消在任务锁后按ID锁读当前分配，按库存ID升序释放；不使用事务早期RR快照里的历史占用。
- 波次异常结束保留已发货成员；未发成员需要确认集货/播种实物退回原库位后解除波次，恢复普通任务，再处理短缺/货损。历史集货/播种记录保留，结束后禁止继续操作。
- 客户退货按原出库分配行追溯批次。原单已发货（或异常关闭且有已发量）才可退；累计退货不得超过该分配行实发量。验收时一次确认合格/不良数量与目标库位，合格可用、不良冻结，同事务落库与回执。此基础版本不含退款、供应商退货、换货、维修。
- 写入命令要求原始幂等键；未知结果保留请求与键供重试。事务失败整体回滚，租户隔离包括租户 0。

## 接口

以下路径以 `/api/v1` 为前缀。写入需 `Idempotency-Key`（去除首尾空白后 1–64 字节）；JSON 中所有 ID 都是字符串。请求拒绝多余字段和尾随 JSON。

| 方法 / 路径 | 权限（另需对应读取权限） | 请求 / 说明 |
| --- | --- | --- |
| POST `/inventory/freeze` | `wms:inventory` + `wms:inventory:freeze` | `inventory_id, quantity, unfreeze, reason`；返回 `inventory_id` |
| GET `/outbound/exceptions` | `wms:outbound:view` | `order_id, keyword, page, page_size`；单号模糊检索，分页最多100 |
| POST `/outbound/exceptions` | `wms:outbound:exception` | `task_id, kind: SHORTAGE/DAMAGE, quantity, confirm_returned: true, reason` |
| POST `/outbound/exceptions/:id/resolve` | `wms:outbound:exception` | `close: false` 重新分配；`true` 关闭剩余；`reason` 必填 |
| POST `/outbound/waves/:id/abort` | `wms:outbound:exception` | `confirm_returned: true, reason`；返回 `wave_id` |
| GET `/outbound/orders/:id/returnable` | `wms:outbound:view` | 原单已发分配行、批次、实发/已退/可退数量；仅为预览，提交仍重新锁定校验 |
| GET `/outbound/orders/:id/return-locations` | `wms:outbound:return` | 同仓启用库位，分页最多100；无需基础资料管理权限 |
| GET `/outbound/returns` | `wms:outbound:view` | `order_id, keyword, page, page_size`；原单号/退货单号检索 |
| POST `/outbound/returns` | `wms:outbound:return` | `allocation_id, location_id, good_qty, bad_qty, reason`；一次验收一个原分配批次，合计至少1 |

异常登记、处理与退货成功返回 `object_id`。客户端随后刷新原单与记录。权限注册表、角色配置和演示/个人体验账号已包含相应授权项；已有自定义角色需管理员按职责授予。

## 操作与恢复

- 库存查询每行“冻结/解冻”，流水展示冻结前后量及原因。Excel 在原列末尾追加冻结量/冻结流水字段。
- 出库单详情“异常与售后”区域登记异常、处理异常、验收退货；侧栏“异常作业”“客户退货”分页追溯。退货凭证保存验收时货品与库位快照。

### 页面更新与批次核对

- 部署新版本后，旧标签页可能仍使用旧脚本。若侧栏缺少“异常作业”“客户退货”，先强制刷新（桌面 Ctrl+F5），再从出库单列表进入详情。
- 页面脚本或样式加载失败时显示刷新恢复入口；由用户选择刷新并打开原目标，不自动刷新或重新提交业务。出库单接口失败时显示单独的重新加载入口。
- HTML 每次使用前须重新验证缓存；带内容哈希的静态资源允许长期缓存，缺失资源返回404，不返回首页 HTML。
- 批次号是入库时确定的追溯标识，不是当前时间。预置期初库存包括 `B20260901`、`B20260905`、`B20260910`；FIFO 分配这些历史批次是预期行为，不能为显示“今天”而改写库存批次。查看库存流水可以核对来源。
- 不良与合格品需要分库位放置时，按各自库位分两次验收，累计上限仍共同计算。
- 未知结果在本机保留原动作、单据标签、参数和请求键，刷新后可恢复。7天内按服务端记录重放；超期/损坏记录禁止自动重发，先核对原单、凭证和流水。跨标签页存储不提供互斥，由服务端数量锁与原键去重裁决。

## 发布与回退

发布时停止旧版本写入，备份后按版本迁移至17，再启动匹配应用。正式启动验证新的余额与数量 CHECK；开发 AutoMigrate 支持从旧余额约束升级。租户0也按精确租户隔离。

16 的回退会在存在冻结余额或冻结/短缺流水时拒绝；17 的回退会在存在异常、退货或已异常结束波次时拒绝。回退拒绝可能留下迁移 dirty 状态，需按迁移规程核对，不能强制删除业务历史或直接清除标记。普通业务入口不删除上述审计；演示重置继续按既有租户规则清理演示数据。
